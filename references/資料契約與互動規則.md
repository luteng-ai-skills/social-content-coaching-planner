# 資料契約與互動規則

## 使用時機

每次建立、讀取或更新內容工作台前完整讀取。本文件是 JSON 欄位、狀態、單題互動與外部操作資料的正式定義。

## 主版本原則

- JSON 是跨對話、跨工具的正式主版本。
- HTML 是操作介面，`localStorage` 只是暫存。
- 匯出 JSON 後才視為可交給下一個 AI 接手的版本。
- HTML 不保存 Token、密碼、Cookie 或 OAuth 憑證。
- 人物思維只保存名稱、本月摘要與確認狀態，不複製完整 Skill。

## 最小 JSON 結構

```json
{
  "schemaVersion": 1,
  "workspace": {
    "id": "唯一識別碼",
    "learnerName": "學員名稱",
    "month": "YYYY-MM",
    "periodWeeks": 2,
    "goal": "本月目標",
    "platforms": ["Facebook"],
    "postsPerWeek": 3,
    "timezone": "Asia/Taipei",
    "updatedAt": "ISO 8601"
  },
  "mindset": {
    "status": "active",
    "skillName": "○○思維",
    "source": "skill",
    "confirmedSummary": [],
    "inferredSummary": [],
    "avoid": [],
    "writingPreferences": {
      "tone": [],
      "sentenceRhythm": "",
      "paragraphStyle": "",
      "lineBreakStyle": "",
      "punctuation": "",
      "openingStyle": "",
      "closingStyle": "",
      "ctaStyle": "",
      "forbiddenPatterns": [],
      "status": "尚未確認"
    }
  },
  "audiences": [],
  "pillars": [],
  "sourceLibrary": {
    "sources": [],
    "caseCards": []
  },
  "articles": [],
  "archive": {},
  "publishingBatch": {}

```

## 受眾

每筆 `audiences` 包含：

- `id`
- `role`: `primary`、`secondary` 或 `notPriority`
- `name`
- `currentState`
- `pain`
- `desiredOutcome`
- `followReason`
- `suitableContent`
- `avoidLanguage`
- `status`: `suggested` 或 `confirmed`

## 內容柱

每筆 `pillars` 包含：

- `id`
- `name`
- `sourceType`: `confirmed`、`inferred` 或 `suggested`
- `sourceNote`
- `audienceIds`
- `readerProblem`
- `purpose`
- `formats`
- `ratio`
- `avoid`
- `status`: `suggested`、`confirmed` 或 `rejected`

已確認內容柱的 `ratio` 總和應為 100；尚未確認時允許顯示警告。

## 文章

每筆 `articles` 包含：

- `id`
- `date`: `YYYY-MM-DD`
- `time`: `HH:mm`
- `platform`
- `pillarId`
- `title`
- `purpose`
- `audienceId`
- `angle`
- `personalPrompt`
- `lengthPlan`: `mode`、`recommendedRange`、`targetChars`、`reason`、`status`
- `evidenceGate`: `status`、`sourceRefs[]`、`confirmedFacts[]`、`missingInfo[]`、`inferenceBoundaries[]`、`checkedAt`
- `appliedStyle`: `tone[]`、`formatting[]`、`source`
- `status`
- `research[]`
- `draft`: `version`、`body`、`updatedAt`
- `revisionHistory[]`: `version`、`date`、`summary`
- `changeRequest`: `type`、`note`
- `publishing`: `account`、`audience`、`media`、`action`、`capability`、`readbackUrl`
- `archive`: `provider`、`destination`、`reason`、`status`、`url`

文章狀態只能是：

`待研究`、`研究完成`、`待補本人觀點`、`寫作中`、`草稿待確認`、`已確認`、`待排程`、`已排程`、`已發布`、`封存`

## 案例與來源庫

`sourceLibrary` 是選填欄位；舊版 JSON 沒有時，以空陣列補齊。詳細欄位與建立方式見 [案例資料卡與來源索引](案例資料卡與來源索引.md)。

- `sources[]` 保存來源名稱、類型、路徑／網址、日期、擁有者、使用邊界與狀態。
- `caseCards[]` 保存案例摘要、來源 ID、時間戳／頁碼／段落、情境、行動、結果、反思、可用主題、缺少細節、敏感性與確認狀態。
- 只有來源可追溯、本人已確認且符合公開邊界的案例，才能寫成本人經驗。

## 研究資料

每筆研究包含：

- `title`
- `eventDate`
- `checkedAt`
- `summary`
- `whyUseful`
- `audienceBenefit`
- `freshUntil`
- `risk`
- `recommendedAngle`
- `decision`: `待確認`、`採用`、`備用` 或 `跳過`
- `sources[]`: `title`、`publisher`、`url`、`publishedAt`、`sourceType`

事實、外部觀點、AI 推論與本人待補立場不得混成同一欄。

## 寫作偏好與篇幅

`mindset.writingPreferences` 只保存人物思維或本人已確認的語氣與排版偏好；未確認的欄位保留空白，不得由 AI 猜測。每篇 `appliedStyle` 記錄本篇實際採用的偏好，方便學員檢查，不複製完整人物 Skill。

`lengthPlan.mode` 使用 `短篇`、`中篇`、`長篇` 或 `自訂`。中文起始參考可用短篇 300～600 字、中篇 700～1,200 字、長篇 1,300～2,200 字，但 AI 必須依平台、主題複雜度、受眾與素材量另給理由；`status` 為 `建議中` 或 `已確認`。不得在學員未選擇前，因預設字數直接成稿。

## 素材充足度

每篇 `evidenceGate.status` 只能是：`未檢查`、`待補資料`、`足夠` 或 `已確認可寫`。

- `sourceRefs[]`：實際讀取來源的名稱、路徑或網址、時間戳／段落定位與用途。
- `confirmedFacts[]`：來源可直接支持的事實及本人已確認觀點。
- `missingInfo[]`：仍缺少的案例、情節、數字、原話或本人判斷。
- `inferenceBoundaries[]`：可以提出但不可冒充事實或本人經驗的推論。

狀態為 `待補資料` 時，文章狀態必須為 `待補本人觀點`，不得建立正文。舊版 JSON 沒有上述選填欄位時，載入後以空白預設值補齊，維持 `schemaVersion: 1` 相容。

## 兩週與四週

- `periodWeeks: 2`：只在月初起算的 14 天安排文章，其餘日期在 HTML 顯示「尚未展開」。
- `periodWeeks: 4`：在選定月份安排完整四週。
- 無論哪種模式，文章正文都逐篇產出。

## 單題互動

每題資料應包含：

```text
問題編號與題目
必要的一句用途說明
2～4 個互斥選項
建議選項與具體理由
回覆方式
```

問完停止。使用者回答前不得預先問下一題，也不得把後續問題藏在同一段文字。

環境支援互動控制項時使用真正的按鈕或選單；純文字環境才使用編號。Cowork 展開的製作頁必須顯示可見的陪跑階段選單、目前位置與下一步，不可讓學員只能從長頁面猜操作入口。

## 暫存與正式保存

- 表單輸入變更後自動寫入 `localStorage`，畫面顯示最後暫存時間與「尚未匯出」狀態。
- 關閉抽屜前先完成待執行的自動暫存；尚未匯出正式 JSON 時，離開頁面需觸發瀏覽器警告。
- 匯出檔名附本機時間，降低同名覆蓋風險；匯出後畫面顯示正式備份時間。
- 匯入 JSON 後讀回學員、月份、文章數與目前階段；無法驗證時不得顯示匯入成功。

## 發布批次

`publishingBatch` 包含：

- `scope`: `兩週` 或 `四週`
- `status`: `未準備`、`待確認`、`已授權待執行`、`部分完成` 或 `已完成`
- `confirmationPhrase`: `確認兩週排程` 或 `確認整月排程`
- `authorizedAt`
- `articles[]`: 文章 ID、平台、帳號、版本、日期、時間、時區、受眾、媒體、動作與讀回狀態

完整卡片出現前的「可以」「幫我發」或選單編號都不算操作授權。任何實質欄位改變，只讓受影響項目回到待確認。

## Notion 歸檔

`archive` 可保存：

- `provider`: `Notion`、`Google Drive`、`Obsidian`、`本機` 或 `未設定`
- `defaultDestinationUrl`
- `destinationType`: `page`、`database` 或 `unknown`
- `schemaMap`
- `checkedAt`

只保存目的地與欄位映射，不保存驗證資訊。第一次取得連結先唯讀，實際寫入前另取確認，寫後必須讀回。
