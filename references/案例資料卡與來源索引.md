# 案例資料卡與來源索引

## 使用時機

當學員提供逐字稿、文章、訪談、語音筆記、書稿或大量 Markdown 素材，且文章需要真實案例與細節時使用。目標是讓 AI 每次只讀取相關證據，不把人物思維摘要誤當完整資料庫。

## 分層

1. **人物思維**：保存判斷原則、價值觀、語氣與排版偏好。
2. **來源索引**：記錄檔案、網址、日期、來源類型與可追溯位置。
3. **案例資料卡**：把一段完整事件整理成可搜尋、可引用的證據單位。
4. **單篇寫作依據卡**：每篇只挑選相關案例，列出已知、缺口與推論界線。

## 來源索引欄位

- `id`
- `title`
- `sourceType`: `逐字稿`、`文章`、`訪談`、`語音筆記`、`書稿`、`網頁` 或 `其他`
- `pathOrUrl`
- `recordedAt`
- `owner`
- `usageBoundary`
- `status`: `可使用`、`需確認` 或 `不可使用`

## 案例資料卡欄位

- `id`
- `title`
- `summary`
- `sourceId`
- `locator`: 時間戳、頁碼、段落或行號
- `peopleOrOrganizations[]`
- `situation`
- `action`
- `result`
- `reflection`
- `confirmedQuotes[]`
- `usableFor[]`: 適合的內容柱、題目或受眾
- `missingDetails[]`
- `sensitivity`: `可公開`、`需匿名`、`需本人確認` 或 `不可公開`
- `status`: `草稿`、`已確認` 或 `停用`

## 建立流程

1. 保留原始檔，不改寫、不覆蓋。
2. 先建立來源索引，記錄可追溯位置與使用邊界。
3. 依完整事件切成案例卡，不按固定字數硬切。
4. 每張卡分開保存來源事實、本人反思、AI 歸納與仍缺資訊。
5. 涉及公司、客戶、數字、結果或引言時，沒有來源定位就標示 `需確認`。
6. 請學員確認案例卡；只有 `已確認` 且符合公開邊界的內容，才能寫成本人案例。
7. 寫每篇文章時只載入相關案例卡；資料不足再回讀原始來源。

## 禁止事項

- 不因來源出現公司、人名或工具名稱，就補寫原文沒有的情節。
- 不把 AI 摘要、外部觀點或旁人描述改寫成本人親身經驗。
- 不把語氣相似當成事實正確。
- 不把整批逐字稿無差別塞進每篇任務。
- 不因案例卡存在，就忽略敏感性、匿名化與本人確認。

## 單篇選取輸出

開始寫作前，先列出：

```text
本篇使用案例：
- 案例卡 ID／名稱：
- 原始來源與定位：
- 可以確認的事實：
- 本人已確認觀點：
- 仍缺資訊：
- 不可越界推論：
- 公開邊界：
```

若「仍缺資訊」會影響文章核心成立，停止成稿並一次只問一個補充問題。
